01 / System context

What talks to what

Everything runs as you, on one machine. The backend is the only thing that touches tool state; both clients go through its API.

R = read only. R/W = Eyrie writes there. Dashed widget box: in PR #20, not on main. Claude Code and Codex write their own transcripts and DBs; Eyrie only reads them.

Read path

The source registry (sources/base.py) holds one object per enabled source. Each has available() and snapshot() and reads the tools' files on request, with caches keyed on file stat where a read is expensive.

Write path

Six declared actions build argv lists for claude, codex or tmux. Two file writers (tasks, agent memory) edit files directly with etags. There is no generic command endpoint.

03 / Key flows

Sequences

Solid arrows are calls; dashed arrows are replies. Diagrams scroll sideways on narrow screens.

3.1 Starting a session

The UI generates the session name and the Claude conversation id before the preview, so the previewed argv is exactly what runs. sessions.start isn't destructive, so no confirm; sessions.stop is, and gets a 428 until confirm: true.

3.2 Browser terminal

Browsers can't set headers on a WebSocket, so the token rides as a subprotocol. The pty isn't the tmux client's controlling terminal, so Eyrie sends SIGWINCH itself after each resize.

Close codes: 4000+status (4401, 4403) from the middleware and 4404 / 4503 from the router are sent before accept, so the browser sees a failed handshake (the server answers HTTP 403). 4429 is sent after accept.

3.3 Summary poll: home page and widget

One endpoint answers "what needs me?" for both views, so they can't disagree. Measured at about 60 ms warm (docs/home-and-widget.md §2).

Attention kindSeverityWhen (summary.py)
cli_missingproblemtmux, claude or codex not found (config path or PATH)
session_exited_errorproblemAn Eyrie session's pane is dead with a non-zero exit status
mcp_failedattentionA configured, not hidden, MCP server appears in the last-known failures
session_idleattentionA live Eyrie session has had no output for sessions.idle_minutes (10). External sessions are never flagged
unpriced_modelattentionA model in the last 14 days has no price, so it counts as $0

3.4 Building the usage index

Claude Code prunes old transcripts, so usage.db is the system of record, not a cache. Scans run inline on request, throttled to once per 10 s; there is no background worker.

One API response is written as several transcript lines that repeat its usage, so summing lines overcounts. Keying on (message.id, requestId) and keeping the max of each counter fixes that and makes rereads idempotent. Codex has only a lifetime tokens_used per thread, so it's reported per model, never per day.

3.5 External session detection

Sessions you started in your own terminals are listed alongside Eyrie's. Only the tool name and a resume target are taken from each command line, because the arguments can hold a prompt.

3.6 Editing tasks or agent memory with etags

Obsidian and the agents edit the same files, so every write carries the etag the client read. The etag is a content hash, so mtime granularity can't fool it.

Tasks (sources/tasks.py)

  • Default file: <vault>/Personal/Tasks.md, created with a header on first add.
  • Task id: sha1(text)[:10], plus -n for duplicates. The checkbox isn't hashed, so toggling keeps the id.
  • Only the target line changes. New tasks go after the last task. CRLF is preserved.
  • Unknown id: 404 with current.

Agent memory (sources/memory.py)

  • Files: ~/.claude/agent-memory/<agent>/*.md (Claude Code subagent memory; paths.agent_memory overrides; the folder itself may be a symlink); no new agent folders.
  • Create uses If-Match: absent. 1 MB per file.
  • Read returns linked_from: other files in the folder that mention this one.
  • Delete moves to ~/.eyrie/trash/agent-memory/<agent>/, timestamped on a name clash.

One process, one port, per user

Native, no Docker: a container can't drive the host's tmux or the host's claude and codex with your credentials.

macOS: launchd agent local.eyrie

  • ~/Library/LaunchAgents/local.eyrie.plist via plistlib, checked with plutil -lint.
  • RunAtLoad, KeepAlive, ThrottleInterval 10.
  • AbandonProcessGroup: restarting Eyrie never kills its tmux sessions.
  • launchctl bootout then bootstrap gui/<uid>.

Linux: systemd user unit eyrie.service

  • ~/.config/systemd/user/eyrie.service, systemd-quoted args.
  • Restart=on-failure, RestartSec=5.
  • KillMode=process: only Eyrie stops, tmux sessions keep running.
  • daemon-reload, enable, restart. Tip: loginctl enable-linger.

PATH capture

launchd and systemd user units start with a minimal PATH, so claude, codex and tmux wouldn't be found. At install, login_path() runs $SHELL -lic 'printf "__EYRIE_PATH__%s__END__" "$PATH"' with only HOME USER LOGNAME SHELL and TERM set, takes the value between the markers (so shell noise doesn't matter), and writes it into the plist or unit. It falls back to the current PATH and warns about any tool missing from it. Re-run make install after pulling changes.

08 / Known limits and next steps

Where it's thin

Limits in today's code

  • Claude Code and Codex are hard-coded. Tool names are literals in the action models (Literal["claude","codex"]), argv building, Runner.binary, external detection (TOOLS, HELPERS), sources and the summary.
  • Masking is by shape. app/masking.py catches secret-named flags and NAME=value pairs, URL passwords and query values, and well-known token formats. A secret with none of those shapes (say, a bare random string as a positional arg) still shows.
  • Polling, not push. Every view polls (Sessions every 4 s, summary every 10 s from each client), and each summary runs ps plus tmux calls.
  • GET /sessions/{name}/screen is served but no page calls it any more; the terminal replaced the screen preview.
  • Cost reads 0–15% low: Claude Code doesn't log some background calls (titles, compaction). The Usage page says so.
  • The terminal limit (8) is a per-process counter, which is fine for the single uvicorn worker Eyrie runs.

Next steps

Tool-adapter layer planned

One adapter per tool (binary, session argv, transcript and usage reader, MCP and plugin verbs, process-detection rules) behind an interface, so Gemini and others can be added without touching the routers.

First-run setup built

app/setup.py: detects tools, suggests session roots from known projects, offers Obsidian vaults, writes ~/.eyrie/eyrie.toml (merged, etag-checked, audited) and applies it live. The UI redirects to /setup until a config exists; /settings edits it later.

Packaging planned

PyInstaller onefile eyrie-server as a Tauri sidecar, frontend/dist as a resource; .dmg, .deb, .rpm from a tag-triggered release workflow; first launch installs the service.

Unified brand mark planned

One mark across the app header (e. tile), favicon, tray icons (widget/make_icons.py) and the landing page.

Widget PR #20

Tray icon by summary.state, macOS cost title, rich menu on all platforms, panel via widget.html; commands summary refresh action add_task open_eyrie get_settings set_show_cost set_autostart start_eyrie hide quit.

Subagents per session idea

List a session's Claude subagents from ~/.claude/projects/<proj>/<session>/subagents/agent-*.jsonl plus each .meta.json (description, agentType, finished). The usage index already reads those transcripts for cost.
